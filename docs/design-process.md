# Design process

How the interface went from idea to code. The solution concept and the layout come from the team; AI tools were used to speed up prototyping.

## 1. Paper sketches (team)

Drawn by hand on 2026-11-14. Top bar with Landmarks, Locator, Favorites and Account; Legend panel on the left; Tools panel on the right; Time/Calendar controls; the Moon view in the center. Photos and label translations in [`sketches/`](sketches/).

## 2. High-fidelity mockups (Google Stitch, AI tool)

Kayky used **Google Stitch** to turn the sketches into interactive mockups. Two screens were produced:

| Screen | What it explores |
|---|---|
| Interactive lunar map | Main layout: layer list, selected-site card, legend, layer filters, measurement tools (polygon, ruler, pin), 3D navigation controls, illumination timeline, elevation color scale |
| M3 mineral spectrometry | The same layout with a mineral-composition layer (titanium and iron content) |

Stitch also produced a design-token file (dark theme, sky-blue primary and amber accent, Space Grotesk for headings and Inter for body text).

**How the mockups are used**

- As a **reference for layout and visual style** only.
- Every number, place label and reading in the mockups (coordinates, radiation, composition, extraction zones, etc.) is a **placeholder generated by the tool**. None of it is used as data. Real values come only from the sources in [`data-sources.md`](data-sources.md).
- Some elements go beyond the current scope and stay **PLANNED**: the M3 mineral layer, GRAIL gravimetry, the mining-polygon tool and the equatorial/far-side views. The MVP focuses on the lunar south pole (see [`milestones.md`](milestones.md)).
- AI-generated images shown on the project page or the site must carry a visible "AI-generated" watermark, as required by the Space Apps rules.

## 3. Clickable prototype (Claude)

A clickable HTML prototype based on the paper sketch, with no real data, was made with Claude to test the flow before coding.

## 4. Implementation (team)

The front end in `frontend/` is written by Kayky, with code drafts from Claude, following the layout above and the decisions in [`decisions.md`](decisions.md).
